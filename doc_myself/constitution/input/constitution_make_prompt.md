## ドキュメント生成ルール

### 共通
- 言語は日本語、英語で併記すること。専門語は初出で簡潔に定義。
- 章立ては「目的→前提→要件→設計→検証→結論→付録」の順。
- 各節は**結論先出し（要点3行以内）**→根拠→図表→補足の順で書く。
- 数値は**単位と許容誤差**を必ず付す（例：1.00 ms ±100 µs）。
- 用語は用語集（/docs/glossary.md）の用語に合わせる。新語は必ず追加。

### 書式
- 見出し：H1は文書タイトル1回のみ、H2以降で階層化（深さ≤3）。
- 箇条書きは最大5点/節、6点以上は表にする。
- 重要語は**太字**、コードは `インライン`、長文コードはフェンス ```言語 指定。
- 図表は「Fig.1」「Table 1」連番。キャプションは”要点”を書く。

### 追跡性・ID
- 要件は ID（SC-REQ-###）、設計項目は SC-DES-###、テストは SC-TST-### を付与。
- 各要件には**対応テストID**を必ず紐付ける（Traceability表を付録に自動生成可能な形で）。

### 種別別テンプレ
- **設計書（design.md）**
  - 目的/非目的、対象範囲、アーキ図、状態遷移、タイミング予算、エラーハンドリング、I/F仕様（引数・単位・範囲）、非機能（RT/安全/ログ）、
- **API仕様（api.md）**
  - 関数シグネチャ、前提条件、引数・戻り値、例外/エラーコード、計算量、リアルタイム注意、使用例（良/悪）
- **テスト計画（test-plan.md）**
  - 目的、適用範囲、合否基準（p95/p99 指標を明記）、HIL手順、ログ取得方法、カバレッジ目標、リスクと緩和策
- **リリースノート（release-notes.md）**
  - 変更点（Why/Impact/RT影響）、既知の問題、移行手順
- **データフロー図**
    - 全体のデータフロー図を作成すること

### 執筆スタイル
- 「です・ます」統一。主張→根拠→数値→影響の順で1段落≤5行。
- 図は**文章なしで意図が通る**よう凡例・単位・前提を書く。
- 禁止：スクショだけの説明、”改善しました”の抽象表現、主観のみ。

### 変更管理
- 章ごとに差分が読める粒度でコミット。メッセージは「SC-###: 要点（<=72文字）」。
- PRテンプレ：目的/変更点/代替案/RT・メモリ影響/テスト結果/リスク。

### 生成AIへのプロンプト規則
- 「対象文書の種別」「目的」「出力先ファイル名」「必要セクション」「Trace IDの採番範囲」を必ず指示。
- 例：『/docs/api.md に HAL-DAC のAPI仕様を作成。範囲は SC-API-200〜249。関数は init/write_ch/write3。各関数に 前提/引数/戻り/エラー/RT注意/使用例 を含める。』
